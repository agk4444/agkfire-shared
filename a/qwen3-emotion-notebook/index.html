If n_gpu prints 1: set BS = 4 and ACCUM = 4 to hold effective batch at 16.

The bug that would have silently ruined the run

Qwen-family sequence classifiers pool the last non-pad token. With pad_token_id unset it takes the last value in the row — on a dynamically-padded batch that is a <pad> position. Training completes, loss looks fine, accuracy is garbage.

Cell 7 sets model.config.pad_token_id and asserts it is not None. Don't delete that assertion.

Hardware notes

  • T4 (sm_75) — no bf16, uses fp16; 4-bit NF4 works
  • P100 (sm_60) — 4-bit unsupported, notebook auto-drops to fp32 + BS 4 (~3× slower)
  • Kaggle assigns the GPU; you cannot choose. Probe first.
